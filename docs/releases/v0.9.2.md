# PipeWireAO 0.9.2: RTC source reconciliation

This receiving source revision preserves the released 0.9.1 prepared metadata
support and restores the RTC development APIs. It is not an installed or
published release receipt.

The baseline is released 0.9.1, commit
`ec57daf83f51ea0e6bd305f2b281fe3d3829f1d2`. The reconciliation retains the
changes from `a7b46ae`, `e57fa07`, `2a95e74`, `bbb7a43` and `bc13c14`:

- Bounded owner-thread ndarray command endpoints and typed receiver roots.
- Nonblocking, bounded MainLoop iteration and native parameter sequence output.
- Filter parameter-copy limits checked before reading the POD body.
- Explicit optional ndarray reference-timestamp publication, including clearing
  omitted timestamps on reused buffers.

The reference-timestamp merge retains the released local `duration` binding
that prevents repeated mutable-field reads from allocating. Released metadata
ABI guards, the minimum JLL 4.0.1 dependency and the
[0.9.1 validation record](v0.9.1.md) remain intact. Development now requires
Julia 1.13 or newer.

## Source validation on 2026-11-06

Julia 1.13.3 ran the full package suite on Linux x86_64 with three default
threads and one interactive thread: **2,315 passing assertions in 81 reported
test sets**, with exit status zero. This includes Aqua, native/private-core
tests, bounded command dispatch and copy limits, MainLoop iteration and the
new reference-timestamp inference and zero-allocation regressions.

The temporary validation environment was
`/tmp/pipewireao-rtc-reconciliation-env-20261106`, with direct PipeWireAO,
PipeWireAO_jll, Aqua, Test and Libdl dependencies. JLL product preferences
selected the client, SPA and support libraries from
`/tmp/pipewire-rtc-reconciliation-sdk-20261106`. That SDK reports native 4.0.2:
released 4.0.1 plus the preserved ndarray owner-loop accessor and version bump.
The released 4.0.1 artifact does not export that accessor.

```sh
PIPEWIREAO_EXCHANGE_TEST_PREFIX=/tmp/pipewire-rtc-reconciliation-sdk-20261106 \
PIPEWIREAO_TEST_LIBRARY=/tmp/pipewire-rtc-reconciliation-sdk-20261106/lib/libpipewire-ao-0.3.so \
julia --startup-file=no --threads=3,1 \
  --project=/tmp/pipewireao-rtc-reconciliation-env-20261106 test/runtests.jl
```

The SDK assertion checks the actual loaded client library. Private-core tests
select the same SDK's daemon and modules through
`PIPEWIREAO_EXCHANGE_TEST_PREFIX`. An initial environment setup omitted a
direct JLL dependency, so the product preferences were not applied; its
loaded-library assertion failed before the suite ran. Adding that dependency
made the selection explicit, and the full suite above passed.

`gen/generator.jl` regenerated the bindings from that SDK's headers with Clang
0.19.3. Its output exactly matches the preserved generated owner-loop accessor
addition; no generated code was edited by hand. The generator emitted its
existing system `timespec` dependency warning.

These are software and private-core checks. They do not establish hardware,
deadline or tail-latency qualification, or validate a published native artifact
containing the new accessor. No package was installed or published.
