# PipeWireAO 0.9.1: released prepared metadata support

PipeWireAO 0.9.1 requires PipeWireAO_jll 4.0.1+0 or newer within native
major 4. Native [PipeWireAO 4.0.1](https://github.com/DarrylGamroth/PipeWireAO/releases/tag/v4.0.1)
includes the optional FGN ABI 8 prepared Port metadata query. Configured strict
metadata requirements now participate in graph construction and admission.
There is no manual patch step and no Julia API change. Existing hosts and Julia
processes must restart after updating to load the new modules and libraries.

The native source is `036e70ee71de11b457ff018c6711988fab03a657`.
The [JLL release](https://github.com/DarrylGamroth/PipeWireAO_jll.jl/releases/tag/PipeWireAO-v4.0.1%2B0)
source is `09c4f4e9f293376fdd1a2cf73a21d8744be66585`, registered at
`6789c63bfc0a55c45feba689a898df3058416389`. The BinaryBuilder recipe pins the
full native source commit. All five Linux/glibc artifact variants built and
passed audit: aarch64 and x86 baseline, AVX2 and AVX512, including the untagged
x86 baseline fallback. Flagged gather instructions were checked as VEX AVX2
encodings by byte-identical assembly rather than suppressing the ISA audit.

## Checks

- A fresh isolated depot installs registered JLL 4.0.1+0, without path overrides
  or library preferences. All three products load and report native 4.0.1.
- All ten downloaded release archives match both the build hashes and GitHub
  asset digests. Julia selects the downloaded AVX2 artifact tree
  `6e32ad2573662e6d93aa1af06c9b5e593c4e4279` on the validation machine.
- `gen/generator.jl` ran against those released headers. Generated bindings are
  byte-identical; the optional FGN descriptor tail does not change the Julia
  client ABI.
- The full SDK suite passes on Julia 1.12.7 and 1.13.3, including Aqua, allocation contracts,
  interrupt ownership and private native control. An override to the released
  4.0.0 library is rejected during initialization.
- Additional live private-core exchange and metadata callback suites pass
  (136 and 18 assertions). Both the daemon and client use the downloaded JLL
  tree, without a local native build.
- The unchanged released Rust 0.2.0 plugin passes the full live integration
  suite against downloaded baseline and AVX2 artifacts, including strict
  prepared metadata and synchronized teardown. Released native 4.0.0 fails
  the same strict requiredness check. See the [Rust proof](https://github.com/DarrylGamroth/filtergraph-rs/blob/737b9105670ea293f42ae3d398f9aa0f4bec3c74/docs/validation/released-host-20261105.md).

## Julia 1.12 allocation correction

Minimum-version testing found a pre-existing 80-byte allocation in each warmed
ndarray write/read pair. The same test reproduces with 0.9.0 and published native
4.0.0 as well as 4.0.1. `Profile.Allocs` identifies a tuple, keyword NamedTuple
and `ExposureTiming` allocation from rereading the mutable `duration` field for
the keyword constructor. Capturing that field once before the `nothing` test
restores inference without changing the constructor, units or metadata values.
The identical focused call now allocates zero bytes on both Julia versions;
all original package tests and zero-allocation thresholds pass.

Eight alternating warmed CPU batches per variant, each with 100,000 pairs,
measured median service cost 618.44 ns before and 347.80 ns after on Julia
1.12.7 with the same released 4.0.1 host. Observed ranges were 611.57–622.87 ns
and 340.39–350.28 ns, with 80 and zero bytes per pair respectively. These are
local unpinned CPU service-cost observations collected alongside other
verification, not a graph latency or tail-latency claim. The exact allocation
change, rather than a system-wide speedup, is the release acceptance result.

[Raw validation logs and focused benchmark/profile scripts](https://github.com/DarrylGamroth/PipeWireAO.jl/releases/download/v0.9.1/PipeWireAO-v0.9.1-validation.tar.gz)
retain both the failing baseline and passing result.

The first SDK run stopped before the interrupt child reached its ready marker;
its temporary child log was not retained, so no cause is claimed. A focused
repeat with retained logs and a subsequent full suite both pass. No production
change was made in response. The header generator emits its existing system
`timespec` dependency warning; the generated file remains identical.

Native runtime checks ran on Linux x86_64. Aarch64 was cross-compiled and audited,
but was not run on aarch64 hardware. No algorithm, processing callback, numerical
coefficient or GPU backend implementation changed in this host/binding release.
